# 콘텐츠 작업 입구

이 폴더에서 콘텐츠 기획·대본·비컷·영상 편집·검수·개선을 이어간다.
시작할 때 `/Users/kim.kkun/WORKING-AGREEMENTS.md`를 먼저 읽고 글로벌 기준을 따른다. 이미 읽은 변경 없는 문서는 반복해서 읽지 않는다.

## “영상 편집하자”라고 하면
- 현재 대화와 작품 `work.md`에서 대상 작품을 확인한다. 명확하면 다시 묻지 않고, 여러 후보이거나 대상이 없으면 어느 영상인지 한 번만 질문한다. 수정시각이 최신이라는 이유로 작품을 선택하지 않는다.
- 이 폴더에서 `python3 tools/open_inputs.py <작품ID>`를 실행해 해당 작품의 `productions/<작품ID>/inputs`를 Finder로 연다. 새 작품이면 합의된 소재로 작품 폴더와 `work.md`를 먼저 만들고 실행한다. 열기 실패 시 경로와 실패 사실을 알린다.
- 수환은 그곳에 촬영 원본·참고자료·음원을 넣는다. 이미 있는 자료는 다시 요청하지 않는다. “넣었어” 등 투입 완료를 확인한 뒤 실제 파일을 검사하고 기존 승인 범위의 편집·검수·내보내기를 이어간다.
- 검토 결과는 해당 작품의 `outputs`에 둔다. 파일을 넣는 것만으로 대화 밖에서 자동 편집이 시작되는 것은 아니다. 비컷 비용·게시·사용자 원문 보호는 해당 기준과 승인 범위를 유지한다.

## 시작
- `guidelines/content.md`와 대상 작품의 `work.md`를 읽고, 이번 단계에 필요한 아래 기준만 읽는다. 사용 대본·채택 컷·편집 프로젝트·검토본은 실제 파일과 원문 결정으로 확인한다.
- 기획·대본은 `guidelines/scripts.md`, 비컷은 `guidelines/b-roll.md`, 편집·검수는 `guidelines/editing.md`를 읽는다. 단계 전환·재개에는 `guidelines/workflow.md`를 적용한다.
- 수환은 화자이며 경험·방향·취향을 판단한다. AI는 구조화·제작·검수를 맡는다. 일화를 지어내거나 사용자 수정 원문을 덮어쓰지 않는다.

## 작품과 기록
- 새 작업은 `productions/날짜_소재명/`에 필요한 파일부터 만든다. 대본·비컷·편집을 별도 프로젝트로 나누지 않는다.
- 작품 `work.md`는 현재 사용 버전·실제 결과·남은 피드백·다음 행동의 입구다. 기존 상세 기록이 있으면 연결하고 같은 상태를 두 벌로 관리하지 않는다.
- 생성 성공·기계 검사 통과·내용 검수·사용자 채택·실제 게시를 구분한다. 변경된 결과에 이전 검수를 자동 승계하지 않는다.
- 피드백은 우선 해당 작품에서 고친다. 기존 기준 누락/적용 실패/입력·도구 문제를 구분하고, 공통 취향은 사용자 확인 없이 확대하지 않는다. 재사용할 개선은 다음 작품에서 효과와 부작용을 확인한다.

## 기존 자료 사본의 범위
- `references/legacy-workspace/`은 2026-09-22 가져온 자료다. 기존 지침 파일은 과거 출처이며 이 폴더의 업무를 Projects의 Orchestrator나 전체 관리 절차로 되돌리는 입구로 쓰지 않는다. 콘텐츠별 기존 사용자 결정과 승인 근거는 보존하고 관련 절에서 확인한다.
- `productions/`·`tools/`의 바로가기는 Before_Bruce 내부 사본을 가리킨다. 원본 Projects에는 쓰지 않는다. 바로가기 파일을 수정하면 내부 사본이 바뀌므로 원문·이전 버전을 먼저 보존한다.
- 복사된 코드의 기본 경로·서비스 상태·CapCut 프로젝트 경로는 실행 전에 확인한다. 복사만으로 도구 이식이나 무인 자동 편집이 완료된 것은 아니다.
- 자동 수집기 설치·예약 작업·기존 CapCut 라이브 프로젝트·인증정보는 이번 복사에서 변경하지 않았다. 복사된 설치/시작 명령을 확인 없이 실행하지 않는다.
