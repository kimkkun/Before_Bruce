# 컷을 시작할 때 쓰는 템플릿과 실행 명령

평소 필독 문서가 아니다. 새 컷·버전 생성 또는 생성물 재개·전달 검사 때 적용한다.

1. 소속 영상과 소재 ID를 확인하고 `init`으로 기존 이름의 폴더만 준비한다. 같은 컷은 기존 번호·경로를 재사용한다.
2. `reserve`로 컷 기록과 다음 버전을 만든 뒤 [컷 제작기록](컷/제작기록.md)의 필요한 장면 설계·검수 항목을 실제 값으로 채운다. 빈 원본/최종본 폴더는 미리 만들지 않는다.
3. **한 버전은 한 생성 작업(job)**이다. 이미지 수정·영상화 모두 다음 번호를 받는다. 실제 입력은 ID·경로·해시로 연결하며 번호로 추정하지 않는다. 결과는 예약된 버전에 저장한다.
4. 생성정보.md의 JSON 블록이 조건/입력/출력의 기계 정본이다. 같은 내용의 별도 최신 JSON 대장을 만들지 않는다. 아래 검수 본문은 [버전 템플릿](버전/생성정보.md)의 해당 항목으로 보완한다. 컷의 현재 채택·승인 상태는 제작기록.md에서만 관리한다.
5. 사용자 확정 후 필요한 경우에만 `03_최종본`에서 승인 버전을 상대 링크로 가리킨다. 편집용 변환은 원본 버전·설정을 기록한다. MP4는 편집 가능한 CapCut 프로젝트를 대신하지 않는다.

## 생성·등록·검사

도구: [artifacts.py](../tools/artifacts.py). Python 표준 라이브러리만 사용한다. 로컬 파일 관리 도구이며 서비스 호출·결제·삭제·외부 전송은 하지 않는다. 아래 ROOT/RECORD/REQUEST/OUTPUT은 실제 절대경로로 바꾼다. 명령 예시는 Projects 기준이다.

```sh
python3 Higgsfield/tools/artifacts.py init ROOT
python3 Higgsfield/tools/artifacts.py reserve ROOT --shot S01_장면이름 --method '03_인물기반 생성' --request REQUEST
# 반환된 생성정보.md의 params로 서비스에 제출 → 실제 job ID 즉시 등록
python3 Higgsfield/tools/artifacts.py bind RECORD --job-id JOB_ID
# 기존 job 완료 확인 → 예약 버전 안으로 원출력 다운로드 → 등록
python3 Higgsfield/tools/artifacts.py finish RECORD --output OUTPUT
python3 Higgsfield/tools/artifacts.py check ROOT
```

REQUEST는 작업보관에 두는 제출용 임시 파일이다. 필드:
- `kind`: image/video
- `params`: 실제 model/prompt/medias 및 설정
- `inputs`: 각 media의 job_id·영상 루트 상대 path·sha256. 참조가 없으면 빈 배열
- `request_note`: 기존 비용 승인 근거·예산/시도 한도. 이 문구는 사용자 승인을 만들어내지 않는다

업로드된 외부 원본은 inputs에 `external:true`를 명시하고 로컬 원본 경로·해시를 기록한다. 생성된 이전 작업을 external로 바꾸어 연결 검사를 피하지 않는다. Soul ID처럼 모델 설정인 값은 params에 그대로 둔다.

입력 ID·파일·해시를 맞추지 못하면 생성 전에 원자료를 확인한다. 진행 중 같은 컷 재예약은 거절되므로 기존 작업을 조회한다. 응답 불명확한 유료 제출은 새로 제출하거나 reserved를 폐기하지 말고 서비스 이력에서 기존 ID를 찾는다. 제출 전 취소는 `fail RECORD --reason 사유`, 서비스가 명확히 실패/취소한 제출 작업은 `fail RECORD --reason 근거 --confirmed-failed`로 남긴다. flag는 실제 실패를 확인한 에이전트의 선언이며 서비스 자동 조회가 아니다.

`check` 실패는 경로·누락 기록·입력 연결부터 고친다. 기계 검사는 구조·파일 참조에 한정하며, 얼굴·연출·영상 전체 재생·사용자 승인은 별도다. 영상 완성/승인으로 바꾸어 보고하지 않는다. 기술 진단·원응답·검수 이미지·편집 코드는 `99_작업보관`에, 사용자 코멘트는 `03_수정기록`에 둔다.

## 적용 범위와 보존

이 명령을 사용하지 않는 임의 셸·서비스 호출까지 가로채는 런타임 훅은 설치하지 않았다. 에이전트는 프로젝트 입구에서 이 실행 경로로 들어와야 한다. 기존 다른 영상은 자동 변환하지 않으며 재개 대상에서 검사 실패하면 근거로 복원하고 이어간다.

같은 보관 묶음 안은 상대 링크를 사용한다. 다른 디스크로 전달하면 원본 포함 여부와 실제 열림도 확인한다. 삭제·백업·유료 생성은 템플릿 사용만으로 승인되지 않는다. 기존 영상/이미지를 덮어쓰지 않는다.
