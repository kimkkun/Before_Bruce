## 현재 범위 — 인터뷰 후 정정

수환은 B-roll 제작 구조보다 **전체 AI 비서 작업장의 원리를 배우고, 새 정보를 기존 규칙과 비교·시험·통합하며 목적을 유지하는 방법**을 원한다고 정정했다. 첫 목표는 원리를 이해해 AI에게 일을 잘 맡기기, 중심 예시는 여러 일을 맡기는 비서다. 로컬 HTML만 보기로 확정했으며 웹 게시를 진행하지 않는다. 전역 규칙을 AI가 자율 변경할 새 범위는 미답이다.

[같은 학습 HTML](../../sandbox/ai-workflow-learning/dist/index.html)을 전체 비서 중심의 쉬운 비유·폴더 지도·실제 감사·개선 시험으로 다시 작성했다. 공식 구조 자료와 로컬 감사를 추가로 위임해 확인했다. 초기 B-roll 보고서는 사이트 전용 로컬 Git의 524ecd1에 보존돼 있다. 아래 조사·검사·게시 기록은 초기 보고서의 이력이다.

현재 확인: 새 HTML의 ID·내부 앵커·로컬 근거 링크와 JavaScript 구문 검사 통과, 별도 에이전트의 내용 검토 완료. 운영 지침의 구조 변경·삭제·유료 실행·웹 게시 없음. 오래된 안내 경로와 프로젝트별 읽기 범위 등 발견 사항은 학습 HTML에 제안으로 남겼다.

수환 요청: 멀티에이전트 조사로 모범사례와 현재 방식의 강점·빈틈을 분석하고, 새로운 작업에도 적용할 수 있게 쉽게 설명하는 HTML 제작. 기존 지침 보완·영상 제작·루트 커밋은 검토 전 보류한다.

## 조사 방법과 판정

- 구조 설계 공식 자료, 검증·영상 평가 공식 자료/원논문, 실제 로컬 지침 감사를 세 에이전트에 나눠 맡겼다. 총괄이 출처와 관찰을 대조하고 HTML 작성 후 감사 담당에게 내용 검토를 다시 받았다.
- 이번 조사는 내장 웹 검색을 사용했다. Exa·Brave·Tavily 유료 API는 호출하지 않았다. 기존 폴더 조사 최대 1달러 승인을 새 조사·영상 생성의 승인으로 확장하지 않았다.
- 관찰: 공통 지침에 근거·완료 기준 대조가 이미 있고, 기존 CapCut에는 검사 실패 시 진행 보류·재시도 제한·피드백 검사 절차가 있다. Higgsfield도 통과 기준·결함 검사·검토 범위·사용자 채택 기록이 있으므로 ‘검증 부재’ 진단은 부정확하다.
- 보완 제안: 버전별 검사 방법·범위·증거·판정, 다음 단계 진행 조건, 장애별 복구·유료 중복 제출 방지, 컷별 예산/시도 한도, 수정 후 유지 조건 재확인. 새 검증 문서를 일괄 만들기보다 기존 생성정보의 결과·검토를 보완한다.
- 새로운 일은 최소 구조부터 정하고 한 사례로 검증한다. 업무 규모에 맞춰 문서화 깊이와 에이전트 수를 조절한다. 특정 폴더 구조를 보편적으로 최적이라고 주장하지 않는다.
- 제안은 아직 운영 지침이나 실행 자동화에 적용하지 않았다. 계정 조회 이력은 영상 생성·수집·검수·최종 편집의 실증과 다르다.

## 산출물 확인

- HTML 내부 앵커·ID 중복 검사 통과, JavaScript 구문 검사 통과.
- 학습용 판정 함수 64가지 조건 조합 검사 통과.
- Aside에서 실제 로컬 페이지를 열고 데스크톱 화면 확인. Apple Events JavaScript 실행은 브라우저 설정에서 제한돼 있어 설정을 바꾸지 않았다. 실제 브라우저의 모든 버튼·모바일 화면을 자동 검증한 것은 아니다.
- 독립 내용 검토 후 기존 9/9 작업 지도 기반과 예시의 생성/삽입 길이 표현을 보완했다.
- 유료 생성·영상 검토·CapCut 편집·복원은 이번 조사에서 실행하지 않았다.
