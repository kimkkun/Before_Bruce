# 03 인물 기반 생성

Soul ID 또는 인물 참고자료로, 직접 촬영한 연기 없이 김꾼이 원하는 상황에 등장하는 장면을 만드는 방식. 실촬영 동작을 옮기는 작업은 [01 내 연기 변환](../01_내%20연기%20변환/README.md)을 따른다.

## 제작 절차 — 2026-09-21 조사 기반 정리

사용자 요청에 따라 기존 시작 체크리스트를 보완했다. 절차는 다음 제작부터 적용하되 아래 신규 방법의 김꾼 결과 개선·반복 성공은 아직 실증 전이다. 특정 색감·렌즈·장르를 수환의 확정 취향으로 간주하지 않는다.

1. **의미와 사건:** 넣을 대사·전달할 의미를 한 문장으로 쓰고, 시작 상태→눈에 보이는 주동작/변화→끝의 결과를 정한다. 얼굴만 닮은 예쁜 장면으로 목적을 대신하지 않는다. 짧은 컷에 독립 사건을 여러 개 넣기보다 분할 가능성을 검토한다.
2. **인물과 참고 역할:** 기존 김꾼 Soul ID의 이름·ID·준비 상태와 관련 컷 기록을 확인한다. 얼굴/의상·체형/공간/핵심 소품/빛·색/동작 참고를 역할별로 구분하고 필요한 것만 쓴다. 반복 인물·의상·장소는 채택 참조를 재사용한다. 새 인물 훈련이나 다각도 시트는 필요할 때만 만든다.
3. **이미지에서 장면 완성:** Soul ID를 지원하는 이미지 모델로 기준 프레임을 만든다. 얼굴 닮음과 별도로 인물의 화면 크기, 상황이 보이는 여백, 전경·중경·배경, 광원 방향, 재질·색, 손과 소품의 접촉, 상대 크기·발의 지지를 검토한다. 레퍼런스는 '멋있다'로만 고르지 않고 어떤 구도·빛·관계를 가져올지 지정한다. 후보 비교는 승인된 비용 범위에서 하며 한 장씩 결함을 고치는 것으로 충분하면 불필요한 배치를 만들지 않는다.
4. **이미지에서 영상으로 전달:** 채택 이미지를 영상 모델의 시작 프레임/참조/Element 등 지원되는 입력으로 넘긴다. Soul ID가 모든 영상 모델에 직접 적용된다고 가정하지 않는다. Soul Cinema는 영화적 이미지 후보이며 필수 경유 단계가 아니다. 웹 UI·MCP의 입력 역할/개수/모델 호환과 비용은 실행 전에 확인한다.
5. **움직임 설계:** 기준 이미지의 고정 요소와 시간에 따라 바꿀 요소를 나눠 쓴다. 행동·물리적 반응·시작/끝 자세와 타이밍을 구체화하고, 카메라는 목적에 맞는 한 움직임 또는 고정으로 정한다. 복잡한 접촉/여러 사건은 컷 분할이나 다른 입력 방식과 비교한다. 'cinematic/8K/카메라 브랜드'만으로 품질이 좋아진다고 판단하지 않는다.
6. **짧은 시험과 원인별 수정:** 필요한 사건을 확인할 수 있는 짧은 구간과 낮은 시험 해상도부터, 실제 모델 허용 범위 안에서 시작한다. 얼굴 문제는 인물 참조, 상황이 안 읽히면 구도·장면, 물리 오류는 접촉·시작 자세, 동작 오류는 행동·시간 지시를 우선 검토한다. 한 번에 주요 변수 하나를 바꿔 비교하고, 같은 실패를 입력 변경 없이 유료 재시도로 반복하지 않는다.
7. **전체 영상·본편 맥락 검수:** 전체 재생 및 문제 구간 프레임으로 얼굴/의상 연속성, 손·접촉·무게, 빛·그림자, 카메라, 사건 완료를 확인한다. 음향이 있으면 직접 듣고 대사·효과음 타이밍을 확인한다. 실제 확인하지 못한 범위는 명시한다. 얼굴 닮음 / 시각적 완성도 / 대사 이해에 도움 / 동작 품질을 별도로 판정한다. 확대·고해상도 재생성도 다시 검수하고, 사용할 구간만 본편에 맞춰 색·소리·길이를 정리한다.
8. **채택과 재사용:** 기존 컷 제작기록에 사용자 평가·채택/보류·다음 행동을, 버전 생성정보에 실제 입력/모델/설정/프롬프트/비용/검수 범위/사용 가능한 구간을 남긴다. 수환 반응과 AI 관찰을 구분한다. 다음 유사 작업은 이 절차와 관련 사례를 먼저 읽고 이전 성공 조건과 실패 원인을 재사용한다.

## 이미지 단계에서 영상화할지 판단

- 김꾼으로 보이는가? 필요한 표정·시선·안경/의상 조건이 맞는가?
- 자막 없이도 의도한 상황과 인물·소품의 관계가 읽히는가?
- 다음 동작이 가능한 시작 자세인가? 손 접촉·크기·무게·광원에 모순이 없는가?

하나라도 핵심 목적에 맞지 않으면 해당 이미지를 그대로 영상화해 해결하려 하지 않는다. 검토·승인 단계는 기존 사용자 승인 범위를 따르며 이 문서가 매 단계의 재승인을 추가하지 않는다.
