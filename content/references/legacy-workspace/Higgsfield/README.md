## 김꾼 콘텐츠 제작에서 사용하기

현재 작업 흐름은 [대본 확정 → 기본 3~5장면 이미지·영상 선제작 → 수환 검토 → 촬영 → 편집·비컷 삽입](../Kim.kkun_contents/methods/workflow.md#대본부터-비컷편집까지--2026-09-21-수환-확정)을 따른다. 도구별로 작업을 끊지 않고 콘텐츠 한 편으로 이어간다. 컷 선정·이미지 검수·영상화는 승인 범위 안에서 에이전트가 수행하며, 매 단계 수환의 지시를 다시 기다리지 않는다. 크레딧 한도·원본 촬영 대기·중복 생성 방지는 위 정본을 따른다.

- [영상별 보관함 전체](../김꾼_영상보관/README.md)
- [직원관리하다 무너지는 사장님 — 비컷 3개](../김꾼_영상보관/2026-09-13_owner-three-points/README.md)

이 폴더에서 위 바로가기로 결과를 볼 수 있다. 파일 원본은 해당 콘텐츠의 촬영본·편집 자료와 함께 보관하고 중복 복사하지 않는다.

## 과거 범위 — 2026-09-20 첫 제작 계획

첫 제작 대상은 김꾼의 토킹헤드 릴스에 넣을 3~10초 내외의 B-roll이다. 용도는 오프닝 훅·중간 비주얼 훅·내용 이해를 돕는 설명용 컷이며, 수환의 말과 이야기를 보조한다. 대본에서 필요한 구간을 고르고 장면·프롬프트를 기획한 뒤 컷 제작·보관부터 검증한다. 전체 릴스 편집은 이후 별도 요청 때 진행한다.

이번 대화는 플랜까지만 요청받았고 생성·편집 자동화는 구현하지 않았다. 다음 제작 요청 때 대상 대본과 기존 자료부터 확인한다. 생성 전 크레딧·모델·비용 승인 범위를 확인하고, 첫 컷으로 생성·다운로드·파일 검토를 시험한다. 마지막 계정 조회(2026-09-20)는 무료 플랜·0크레딧, Soul 2 캐릭터 4개와 Elements 7개 확인이며 다음 실행 시 다시 조회한다. 앞서 승인한 최대 1달러는 폴더 설계 조사 비용으로, 영상 생성 승인이 아니다.

## 실제 영상 파일의 위치

영상 한 편의 생성 자료는 [김꾼 영상 작업장](../김꾼_영상보관/README.md)의 해당 편 안에 둔다. 공통 제작법과 생성 파일을 중복 보관하지 않는다.

```text
김꾼_영상보관/날짜_소재ID/99_작업보관/Higgsfield/
├── 01_내 연기 변환/
├── 02_상황 장면 생성/
└── 03_인물기반 생성/
    └── S01_장면이름/
        ├── 제작기록.md
        ├── 01_원본참고/
        ├── 02_생성버전/    # v001, v002… 각각 생성정보와 결과
        └── 03_최종본/      # 사용자 확정 버전 연결
```

새 컷은 [공통 템플릿](_templates/README.md)의 생성·등록·검사 명령으로 시작한다. 기존 영상에는 빈 폴더를 일괄 추가하지 않는다. 원본은 기존 위치를 연결하고, 장면 번호는 해당 영상의 장면표와 맞춘다. 제작 방식이 달라져도 같은 컷의 번호를 유지하고 이전 시도를 연결한다.

컷별 현재 상태·원문 코멘트·채택 이유는 `제작기록.md` 하나에, 버전별 실제 입력·설정·비용·다운로드 결과는 각 `생성정보.md`에 둔다. 서비스 URL만 남기지 않는다. 모르는 값은 미확인으로 두며 같은 조건의 재생성이 동일한 결과를 보장하지는 않는다.

전체 영상의 상태는 기존 영상별 비교 기록에서 컷 기록을 연결한다. CapCut 프로젝트는 컷마다 복제하지 않고 영상 단위로 보존하며 [편집·복원 확인 항목](_templates/영상편집확인.md)을 사용한다. 최신 검토본·발행본·이전 버전은 [기존 보관 절차](../Kim.kkun_contents/README.md#영상-파일-보관)를 따른다.

## 개선 기준

지침 변경은 [공통 지침의 「지침 관리」](../WORKING-AGREEMENTS.md)를 따른다. 방식별 README에는 현행 기준만, 원문 코멘트와 성공·실패는 컷 기록에 둔다. 여러 영상에 적용할 취향은 수환의 공통 적용 확정 후 반영한다. [조사 근거](references/2026-09-20_제작관리조사.md)는 설계 검토 때만 읽는다. [AI 워크플로우 학습·감사](references/2026-09-20_AI워크플로우_조사.md)도 구조 보완을 검토할 때만 읽는다.

연결 확인(2026-09-20): Codex 전역 MCP `higgsfield` 등록·OAuth 인증 후, Codex app-server의 실제 MCP 호출로 크레딧·Soul 캐릭터·Elements 목록 조회 성공. 기존 대화의 도구 목록이 미갱신돼도 인증된 app-server 경로로 조회 가능함을 확인했다. 작업 시 실제 상태를 다시 조회한다. 생성·자동 수집·외부 백업은 실행하지 않았다.
