# Kim.kkun_contents — 작동 지침

> 김꾼 콘텐츠 스튜디오. 릴스 기획+대본 + 블로그 글. 자체 저장소 — 커밋 메시지가 로그(`logs/`는 2026-09-08 은퇴, 옛 일지는 그대로 둠).
> **분업 (헌법): 수환 = 화자, AI = 편집자·구조 설계자.** 원료(생각·경험담)는 수환에게서 나오고, AI는 구조화·검수·확장만 한다. 입말은 수환이 촬영하며 입힌다.
> **영상 길이·30초 벽 정본**: 기본은 60~90초. 앞에서 이야기의 구조를 예고하고 이어서 볼 이유가 분명하면 2분 이상도 허용한다. 길이에 맞추려고 필요한 내용을 자르거나 반복 설명으로 늘리지 않는다. 길이 불문, 핵심 주장·죄 전환·고백·서사 정체성은 도입 상황극을 포함한 영상 시작부터 30초 이내에 드러낸다(평균시청 16~35초 실측, archive.md). 측정은 [세션 절차](methods/workflow.md#대본-세션-카드-확정-후)를 따른다. 2026-08-20 기준을 2026-09-13 수환이 “맞어 그렇게 해야돼 통일시켜줘”로 재확인.

## 읽는 순서
1. `context/kimkkun-mind.md` 사고방식·세계관·거부 목록 — **필독**
2. `context/audience.md` 청자 정의 — **필독**
3. `archive.md` 발행 이력·성과 원장 — 기획 세션 시작 시 최근 10건. 터진 패턴은 변주, 죽은 패턴은 금지
4. `context/voice-corpus.md` 검증 대본 원문 + 패턴 — 대본 작업 시 필독(규칙보다 원문이 우선). 빌드인퍼블릭(사건 파일·오리진·모집) 대본은 `context/voice-corpus-build.md`도 함께 읽는다.
5. `methods/workflow.md`는 **생산 규칙**과 이번 작업에 해당하는 절을 읽는다: 기획 → 기획 세션 / 대본 → 대본 세션 / 편집 → 영상 편집 세션 전체 / 발행 반입 → 발행 후 / 성과 → 성과 리추얼. **원문 수정·버전 저장·발행본 연결 전에는 대본 세션의 ‘AI 초안·수환 수정본·실제 발화본 보존’ 항목도 필수**다. 복합 작업은 해당 절을 함께 읽고, 분류가 모호하거나 필요한 기준을 못 찾으면 전체 절차로 넓힌다. 이 선택 읽기는 위 사고방식·청자 필독과 아래 검수 기준을 면제하지 않는다.
   - 대본 확정 직후에는 같은 문서의 「대본부터 비컷·편집까지」도 적용해 기본 3~5장면의 선제작으로 이어간다. 비용·촬영 원본 조건은 해당 절을 따른다.
6. 영상 편집은 `methods/workflow.md`의 「영상 편집 세션」에서 지정한 현재 상태·공통 기준·필요한 근거만 읽는다. 과거 자료 전체를 기본 로드하지 않는다.
7. `methods/reels-script.md` 릴스 / `methods/longform.md` 블로그 — 해당 작업 때만

## 검수 에이전트
- 수환에게 제출할 완성 대본·블로그 초안은 작성자와 별도 에이전트가 검수한다. 사고방식·청자는 `context/kimkkun-mind.md`·`context/audience.md`, 실제 경험·발화는 수환의 원문과 해당 제작물에 대조한다.
- 릴스는 `methods/reels-script.md` §5와 `methods/workflow.md`의 대본 세션, 블로그는 `methods/longform.md`를 적용한다. 성과 주장은 `archive.md`와 관련 `metrics/` 원본의 측정 시점·누락·가설 구분을 확인한다.
- 더크루 정책을 언급하면 [더크루 기획 지침](../the-crew-strategy/CLAUDE.md)에 따라 공통 제품 원칙과 실제 Linear의 관련 이슈 본문·승인 댓글에서 최신 승인 범위를 확인한다. 옛 결정 문서는 과거 근거 조사에만 사용하고, Linear를 확인하지 못하면 현재 정책 미확인으로 표시한다. 결과 제출·보완·기록은 공통 위임 절차를 따른다.
