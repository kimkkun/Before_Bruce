# 김꾼 영상 자막·연출 기준 — 수환 수정 사례

2026-09-10 수환 요청으로 기록. 목적은 다음에 원본 영상을 받으면 전사·자막·반복/공백 컷편집·확정된 스타일 적용까지 이어서 수행하는 것. 전체 실행 순서는 [자동화 안내](automation.md#2026-09-10--capcut-연결자막컷편집-기준)에 둔다. 이 문서는 자막의 분할·글꼴·크기·위치·강조 기준 정본이다. 한 줄·의미 단위 등 명시 기준을 유지하며, 아래 2026-09-18 사례를 최신 연출 참조로 함께 적용한다. 월말 편 v1~v5는 비교 이력으로 보존한다.


## 적용할 기준과 과거 사례 구분

- **확정된 공통 취향:** 바로 아래 「수환이 명시한 기준」과 사용자가 확정한 기존 설정을 적용한다. 9/19 브금·강조음 교정도 같은 오류의 재발을 막는 기준이다.
- **연출 참조:** 「최신 연출 참조 — 2026-09-18」은 실제 수정 사례다. 명시 확정과 관찰 가설을 구분하고 개수·배율·게인을 모든 영상의 고정 공식으로 만들지 않는다.
- **과거 버전:** v1~v5는 비교·복원 근거다. ‘현재’라는 옛 표현은 그 기록 시점이며 지금 편집 상태가 아니다. 확인할 스타일의 해당 절만 찾아본다.
- 영상별 현재 상태는 각 편 `video-comparison.md` 한곳에서 관리한다. 여기에는 진행 현황을 누적하지 않는다. 정보 읽기·갱신 순서는 [영상 편집 세션](workflow.md#영상-편집-세션)을 따른다.

## 수환이 명시한 기준

- **스티커 배치 — 2026-09-19 수환 확정:** 중앙에 더 크게 배치하고 대사에 맞춰 종류를 늘리는 방식을 다음 영상에도 적용하되, 크기·개수·위치·시점은 장면별로 조절한다. owner-emotions v004의 11개나 개별 배율을 고정 공식으로 쓰지 않는다. 즐겨찾기 출처 제한은 유지한다. 근거: [직접 수정 비교](../drafts/2026-09-19_owner-emotions_video-comparison.md#v004--사용자-직접-수정본-비교-2026-09-19), 질문에 “다음 영상에도 적용하되 장면별로 조절”로 답변.

- **썸네일 포함 — 2026-09-18 확정:** 영상 제작 시 완성 영상과 함께 별도 썸네일 이미지도 만든다. 실제 촬영본에서 표정·시선이 좋은 컷을 골라 기존 김꾼 피드처럼 굵은 흰색 글씨·검은 테두리/그림자로 짧은 제목을 배치한다. 얼굴을 가리지 않고 축소·잘림 시 가독성을 검수한다. 썸네일 문구는 해당 영상에 맞게 작성한다. 첫 제작 사례는 `2026-09-13_three-causes/02_AI편집/thumbnail-v001.png`이며 사용자 디자인 확정 전 시안이다.

- **스티커 출처 — 2026-09-18 확정:** 수환이 톤앤매너를 맞춰 골라둔 **CapCut → 스티커 → 내 보관함 → 즐겨찾기**에 있는 스티커만 사용한다. 편집할 때 현재 즐겨찾기 목록을 확인하고 그 안에서 대사에 맞게 선택한다. 전체 라이브러리·검색 결과·외부 스티커를 임의로 사용하지 않는다. 적절한 것이 없으면 해당 구간의 스티커를 생략한다. 즐겨찾기 여부를 확인하지 못한 리소스는 사용하지 않는다.

> “무조건 1줄 안에 들어오게 해야 되고 … 저렇게 의미 단위로 나눠야 … 내가 읽어보면서 어색하지 않게 나눈 … 자막이 가운데에서 살짝 아래로 위치를 옮겼고 … 자막을 저런 단위로 나누었다는게 핵심”

- **자막은 항상 한 줄.** 줄바꿈 문자만 없애는 것으로 끝내지 않고, 실제 영상의 폰트·배율·화면 폭에서 자동 줄바꿈 없이 들어오는지 확인한다.
- **분할은 의미와 실제 발화의 흐름이 우선.** 동일한 글자 수·시간·단어 수를 채운 뒤 자르는 방식은 사용하지 않는다. 짧은 구도 읽을 때 자연스러우면 독립 자막으로 둔다. 문장 전체가 끝나야만 전환하는 것도 아니다.
- **크기와 위치는 이번 수환 작업본을 기본 참조로 사용.** 화면 중앙보다 살짝 아래, 가로 중앙. 한 줄에 안 들어가면 의미를 나눠 다음 자막으로 넘긴다. 맞추려고 자막마다 글자를 더 작게 만들지 않는다.
- 관찰로 추정한 분할 요령은 아래 실제 사례로 검증하고 새 피드백에 따라 고친다. 사용자에게 자신의 감각을 완전한 문법 규칙으로 설명하라고 요구하지 않는다.

## 최신 연출 참조 — 2026-09-18 직원들 망가지는 세 가지

AI 편집본과 수환 직접 수정본을 전체 트랙으로 대조하고 CapCut 대표 미리보기에서 확인했다. [상세 비교·스냅샷·리소스·검증 한계](../drafts/2026-09-13_three-causes_video-comparison.md#수환-수정본-대조--2026-09-18)를 정본으로 삼는다. 다음 편은 이 사례의 대사별 연출을 추가 참조한다.

- **서비스 화면 크기/자막:** 작은 인셋 대신 세로 화면을 크게 채워 UI를 읽게 한다. 이번 6개 배율은 기존0.84→약1.02~1.09. 서비스 화면에서도 자막은 평소 중앙보다 살짝 아래 높이로 유지하되 실제 설명 UI와 겹치는지 확인한다. 자료가 나왔다는 이유만으로 자막을 맨 아래로 보내지 않는다.
- **스티커:** 로딩·노동·해골·혼란·확성기·물음표·우는 표정 등 13개 추가. 대사의 상황·행동·감정에 대응하는 작은 반응으로 사용했다. 아래 수환이 명시한 즐겨찾기 제한 안에서 고르고, 일정 간격으로 채우거나 개수를 복제하지 않는다.
- **강조 묶음:** ‘아무도 안 알아주는 구조’, ‘사장님은 다시 하래요’, ‘바로 여기예요’처럼 중요한 말에 빨간 줄+글자 크기+얼굴 확대+타격음을 함께 검토한다. 이번 추가 얼굴 확대120~125%는 고정 컷 배율이다.
- **자막의 역할:** 기본11·밀크셔벗·한 줄 유지. 속마음/칭찬 인용은 연두색 효과로 구분, 자기소개는 별도 효과·크기15. 끝의 병렬 문구를11→13→16으로 키운 사례. 일반 강조13 외14/15/16을 모든 문장에 적용하지 않고 역할에 맞게 쓴다. 브랜드 표기는 혼재하므로 영문 일괄 변경 규칙으로 삼지 않는다.
- **소리:** 서비스 화면 6곳 모두 클릭음을 등장 약1~2프레임 전에 배치. 핵심 말에는 타격, 마무리에는 북 악센트. AI가 놓쳤던 월말 편의 화면 등장 클릭을 다음 제작 체크에 포함한다.
- **BGM:** AI본보다 약9.6~13.6dB 크게 조절했다. 목소리는 그대로. 이번 소스의 -18/-14/-18dB를 고정값으로 복제하지 않고 음악도 살아 들리는 균형을 실제 혼합음으로 검수한다.
- **2026-09-19 오류 교정:** 수환이 이번 편의 브금 미출력·빨간 강조의 클릭음을 지적했다. 화면 등장 클릭과 강조 타격·마무리 북의 역할을 유지한다. 적용 파일명만 보고 검수하지 말고 재열기 후 음원 동일성과 실제 출력 소리를 확인한다. 내부 ID 재사용 방지는 [자동화 안내](automation.md#단계별-실행-확인--2026-09-19)를 따른다.
- **컷 마무리:** 추가2.97초를 세 곳에서 삭제. 무음 검출만으로 끝내지 않고 문장 연결·늘어진 호흡·반복을 들어 검사한다. 최종 길이 변경 뒤 음악 끝 페이드와 자막1프레임 잔여도 재검사한다.

이번 편의 정확한 리소스·타이밍·크기는 연결한 수정본을 읽는다. 캡컷 타임라인 편집, 실제 혼합음 전체 청취, 수정본 내보내기는 이 분석 작업에서 수행하지 않았다. 스티커의 배치 의도 등은 관찰에 근거한 적용 가설이다.

## 5차 수정 — 수환 편집 완료본 분석 (현재 상태)

수환이 “편집 끝났거든? 확인해봐 분석해봐 그리고”라고 요청한 실제 저장본을 v4와 대조했다. [v5 프로젝트·추가 미디어 목록](../drafts/2026-09-09_month-end-twice_edit-style-v5.zip)에 보존. 추가 촬영/화면 녹화/이미지/음원은 영상 보관함 `01_원본`에 복사 후 SHA256 일치 확인. 사용자의 편집 완료 진술이며 내보낸 최종 MP4·발행 완료는 미확인이다.

검증 범위: 프로젝트 설정·타이밍 비교, 추가 소스 영상 대표 프레임 시각 확인. 완성 렌더링 전체 재생·혼합음 청취는 하지 않았다. 아래 해석을 효과 검증이나 사용자 확정 규칙으로 혼동하지 않는다.

### 구성 변화와 적용 가설

- **95.233333→102.8초:** 앞에 **7.566666초 상황극**을 추가했다. 주방/홀에서 일하는 장면에 ‘민수야 니가 시급이 얼마지?’ → ‘민수야 니가 이번달 몇시간 일했지?’ → ‘사장님’ → ‘월급 계산이 틀리잖아!!’ 대화 자막. 마지막 장면은 약232% 확대, ‘어?’는 크기14·약-14.49도 회전·위치 이동. ‘왼쪽’ 전환0.466666초 사용. 해석: 설명 전 현장 대화로 문제를 구체화하고 반응을 확대해 보여주는 도입.
- **상단 제목:** ‘Pov: / 자영업자 / 월급 주는 날 상황’이 0~10.966666초 표시, 마지막0.5초 페이드 아웃. 제목은 3줄이며 본문 한 줄 자막과 역할이 다르다. 본문 한 줄 원칙을 자동 폐기하지 않는다. 제목 다중행을 앞으로 공통 허용할지는 사용자 확인 전 관찰 사례로 둔다.
- **본문 보조 화면:** 25.93~31.07초 근무표 화면, 34.00~42.43초 추가 근무표 화면. 53.43~66.30초 내 정보/근무 기록 녹화(3개 클립), 78.23~82.60초 매장 체크 화면, 84.87~88.43초 AI 관련 게시물 녹화(2배속). 대표 소스 프레임에서 화면 내용을 확인. 녹화마다 배율·위치가 다르며 실제 프로젝트 값 보존.
- **14.70~16.83초 이미지**도 추가됐다. 이것은 photo 재료이며 별도 sticker 트랙으로 저장되지 않았다. 화면상 이미지의 기능을 리소스 타입만으로 스티커 규칙이라 단정하지 않는다.
- **강조 보강:** ‘한 번에 계산시키는 거죠’(66.30초)가 크기13·빨간 줄·약130% 영상 확대와 타격음으로 강조됐다. 해석: 기능 설명은 서비스 화면으로, 핵심 결과는 얼굴과 강조 자막으로 돌아오는 편집 흐름.
- **음향:** 효과음 **15개/5종**(기존4종+마우스 클릭), BGM4개 클립. 클릭은 화면 녹화 시작 약0.10~0.20초 전에 놓인 5개, 게인 약-5dB. 기존 강조 효과음은 대체로-7dB. 도입에서 본문으로 넘어가는 바람 효과는7.20초, 약-10.78dB.
- **BGM:** `ZISO - The Nutcracker - ZISO Remix.mp3`, 전체0~102.8초, 게인 약-24.46dB. 27.23/55.50/83.53초에 클립 경계, 후반은 원곡27.633333초부터 재사용. 시간축 공백은 없지만 반복 경계가 귀에 자연스러운지는 청취 검수 필요. 페이드 재료는 없다. 음량 수치는 클립 게인이지 체감 음량/LUFS가 아니다.

### 다음 자동화에서 추가할 단계

본문 컷·자막·강조 뒤에 **상황극 자료 선택 → 도입과 제목 배치 → 발화에 맞는 서비스 화면 선택/구간 추출 → 화면 등장 클릭음 → 전체 BGM 길이/반복과 음량 조절**을 검토한다. 소스 자료가 없으면 현장 장면·실제 서비스 시연을 임의로 만들어 채우지 않는다. 도입 길이7.57초·각 화면 배율·특정 음악을 모든 영상의 고정 규칙으로 삼지 않는다.

### 남은 검수 포인트

- 상황극 종료7.57초보다 제목이3.40초 더 유지되어 본문 도입까지 걸친다. 의도인지 확인할 항목이며 자동으로 오류 처리하지 않는다.

- 11.90초 ‘시급은 시급대로,’ 뒤 빈 줄 문자는 남아 있다. 도입 제목3줄과 이 잔여 문자를 구분한다. 최종 화면 한 줄 검수는 미실행.
