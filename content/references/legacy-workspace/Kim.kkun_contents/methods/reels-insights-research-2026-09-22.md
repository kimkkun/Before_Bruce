# 릴스 성과를 다음 제작에 반영하는 방법 — 조사·설계안

조사일: 2026-09-22. 수환 요청: 모범사례, 객관적인 시청 반응 확인, 소재·후킹·대본·구조 개선, 정보 관리 방식 조사.
상태: 조사 결과와 제안. 새 제작 규칙으로 자동 확정하거나 기존 지침·대본을 변경하지 않았다.

## 1. 이번에 실제 확인한 범위

- 기존 수집: 최근 10개 게시물의 조회·도달·좋아요·댓글 수·저장·공유·평균/총 시청시간. 댓글 본문·정확한 이탈 시점은 수집하지 않았다.
- 공식 API 추가 검증: `reels_skip_rate` 성공. API 설명은 최초 재생 중 첫 3초 안에 넘긴 조회의 비율이다. `views`에는 재생 집계 차이가 있으므로 조회수×스킵률로 정확한 이탈 인원 역산 금지.
- 9/22 01:12경(KST) 누적 스킵률: 최신 ‘직원이 눈치 보는 이유’ 49.7%, 8/22 ‘잘하는 직원부터 떠나는 이유’ 27.9%. 게시 후 경과 시간·노출 시청자가 달라 원인이나 승패는 확정하지 않는다. 현재 정기 수집기에는 이 지표가 아직 추가되지 않았다.
- 최신 게시물의 `thumbnail_url`, `media_url` 응답 성공. URL 제공과 실제 영상·대본 분석 완료는 다르다. 표시되는 커버 및 최종 파일 일치 확인이 필요하다.
- Aside 최신 릴스 웹 인사이트: 조회 5,103, 팔로워 조회 비중 54.8%, 비팔로워 45.2%, 프로필 활동 2, 팔로우 2 표시 확인. API에서 follows가 미지원이어도 웹에서는 팔로우 2가 확인됐다. 앞으로 ‘팔로우 확인 불가’라고 일반화하지 않는다. API 원본과 다른 시각·화면에서 관측한 값이므로 기존 원본을 덮어쓰거나 다른 시각 조회수로 전환율을 계산하지 않는다.
- 해당 웹 인사이트 접근성 화면에는 시간대별 유지율 곡선이 나타나지 않았다. 모바일 Instagram/Edits의 본인 계정 제공 여부와 자동 추출 가능성은 미확인이다. 평균 14.8초를 ‘14.8초에서 이탈’로 읽을 수 없다.
- 원본: `metrics/instagram-capability-check-2026-09-21T16-12-29-742Z.json`. 웹 관측은 위 시점의 화면 확인 기록이며 API 응답과 구분한다.

## 2. 찾아본 모범사례와 적용 범위

### Instagram 실제 실험 사례: 바꾸는 요소를 한 개로 제한

Buffer 작성자가 같은 영상에서 음성만 내레이션/현장음/유행 음원으로 바꿔 Trial Reels를 비교했다. 유행 음원 버전의 조회가 내레이션보다 24%, 현장음보다 33% 높았지만 평균 시청은 내레이션과 같았다. 다음 실험을 내레이션+음원 조합으로 정했다. 교훈은 특정 음원 사용이 아니라 질문→한 요소 변경→서로 다른 지표 확인→다음 실험의 연결이다. 단일 작성자·작은 표본의 자기보고여서 김꾼의 효과 크기로 일반화하지 않는다.
[Buffer 직접 실험](https://buffer.com/resources/instagram-trial-reels/)

Meta 공식 Trial Reels는 비팔로워에게 먼저 배포하며 약 24시간 뒤 성과를 볼 수 있다. 공식 문서의 72시간은 자동 전체 공개 판단 창이다. 김꾼의 7일 성과 비교 기준을 대체하지 않는다. 일반 릴스와 Trial을 같은 표본으로 섞지 않는다. 서로 다른 게시물이 무작위로 같은 시청자 집단에 배정된다고 보장되지 않아 정밀한 인과 A/B 테스트로 부르지 않는다. 본인 계정에서 기능 사용 가능 여부는 별도 확인. 실제 시험 게시·자동 전체 공개는 이번 조사 범위가 아니다.
[Meta Trial Reels](https://about.fb.com/news/2024/12/trial-reels-try-content-non-followers-first-see-what-perfoms-best/)

### 구간 분석: 유지율과 실제 발화를 함께 읽기

Meta는 2023년 Instagram의 순간별 Retention Chart 도입을 발표했고 Edits에는 skip rate 기반 피드백을 안내한다. 출시 발표가 현재 본인 계정의 모든 화면/API 제공을 보장하지는 않는다.
[Meta 유지율 발표](https://about.fb.com/news/2023/11/new-ways-to-create-content-on-instagram/)

YouTube 공식 가이드는 급락 구간의 이탈/건너뛰기, 재시청 상승 구간, 강한 장면을 앞당기는 검토를 안내한다. 상승은 흥미뿐 아니라 이해가 어려워 되돌려 본 경우일 수도 있다. 가져올 것은 ‘곡선+실제 장면+대안 설명’의 분석 방법이며 YouTube의 그래프 정의·30초 기준·기능 제공 조건을 Instagram에 그대로 옮기지 않는다.
[YouTube 구간 분석](https://support.google.com/youtube/answer/9314415?hl=en)

## 3. 무엇을 평가하고 무엇을 알 수 없는가

| 제작 질문 | 확인할 근거 | 다음 제작에서 시험할 것 | 한계 |
|---|---|---|---|
| 도입이 넘겨지는가 | 3초 스킵률 + 실제 첫 3초 발화/첫 화면/음성 | 첫 문장·첫 화면·상황 제시 중 하나 | 훅 문장 때문인지 소재·노출 대상 때문인지 단독 수치로 분리 불가 |
| 설명이 늘어지는가 | 구간별 유지율 원본 + 시간 표시된 최종 발화 | 중복 설명 축약, 구체 사례 선배치 | 평균 시청만으로 특정 문장을 범인으로 지목 불가 |
| 내용이 전달 가치가 있는가 | 공유 수와 조회 대비 공유율, 구체 반응 | 사장님이 전달하고 싶은 문장/상황의 표현 | 누가 어떤 초에서 공유했는지 집계 API로 알 수 없음 |
| 썸네일이 맞는 기대를 주는가 | 실제 커버·첫 화면·내용의 일치, 가능하면 유입면별 성과 | 커버 문구/구도 중 하나 | 현재 썸네일 노출·클릭 수 미확보. 전체 조회를 썸네일 CTR로 읽지 않음 |
| 사업 목표에 기여하는가 | 게시물 팔로우(UI), 별도 추적한 가입/신청 | CTA 위치·내용 | 계정 팔로워 증가를 특정 릴스 전환으로 대체하지 않음 |

댓글은 ‘이 문장에 공감’, 질문, 반론, 적용 경험, 신청 키워드, 작성자 답글을 구분한다. 키워드 이벤트의 댓글 증가를 내용 공감 증가로 단정하지 않는다. 반응 원문은 전체 시청자를 대표하는 설문이 아니다. 현재 댓글 관리 API 권한은 허용하지 않았으므로 본문 자동 수집을 이미 가능하다고 보고하지 않는다.

## 4. 정보 관리 제안: 게시물 ID를 기준으로 연결한 다섯 기록

Notion 공식 관계형 데이터베이스/콘텐츠 달력도 서로 다른 기록을 연결하는 구조를 사용한다. 이를 참고하되 새 유료 도구나 Notion 이전은 필요하지 않다. 기존 저장소의 원본·대본·성과 기록을 활용한다.
[Notion 관계와 집계](https://www.notion.com/help/relations-and-rollups)
[Notion 콘텐츠 달력](https://notion.notion.site/Content-calendar-f98a50de5c2f4349ba7427533031ec8a)

| 기록 | 최소 정보 | 저장/연결 제안 |
|---|---|---|
| 게시물 카드 | media_id, permalink, content_id, 게시 시각, 목적, 소재, 대상, 영상 길이, 일반/Trial/광고 여부 | 기존 발행 기록에 연결. 제목·날짜만으로 매칭하지 않음 |
| 제작물·구간 | 확정 대본 버전, 실제 최종 영상, 시간별 실제 발화, 커버 파일, 첫 화면, 구간 시작/끝과 역할 | 기존 drafts/published/영상보관 경로 참조. 실제 파일 해시·버전 보존 |
| 성과 관측 | media_id, collected_at, 게시 후 경과시간, 지표명/값/단위/출처/집계 범위/누락 사유 | metrics 원본 누적. API·UI·수동 판독 분리. 기존 원본 수정 금지 |
| 실험 | experiment_id, 가설, 바꾼 요소, 비교 게시물, 주요 지표, 악화 방지 지표, 관측 창, 결과 | 원장에 실험 기록 연결. 일반/Trial·광고·목적 다른 자료를 분리 |
| 학습 | 관찰 사실, 해석 가설, 대안 설명, 근거 ID, 반례, 적용 범위, 검증 상태, 다음 실험 | 성과 원장에 기록하고 확인된 교훈만 다음 기획에서 참조 |

운영 원칙 제안:
- 대본 초안과 실제 업로드 발화를 분리한다. 편집에서 빠진 문장으로 시청 반응을 해석하지 않는다.
- 파일 원본은 기존 폴더에 두고 경로·해시로 연결한다. 웹 미디어 URL은 영구 원본 경로로 간주하지 않는다.
- 계획 단계부터 유지되는 콘텐츠 ID와 게시 후 media_id를 연결한다. 기존 등록기의 content_id는 영상·대본 해시에 따라 바뀌는 제작 버전 ID이므로 영구 기획 ID와 구별해야 한다.
- 조회표는 원본에서 다시 만들 수 있는 출력물로 취급한다. 원본 관측과 해석을 한 셀에 덮어쓰지 않는다.
- 학습 상태는 관찰/가설/반복 지지/반박/보류로 표시한다. ‘반복 지지’도 통계적 인과 입증이라는 뜻이 아니다. 근거 없는 보편적 스킵률 합격선이나 종합점수는 두지 않는다.
- 팔로우·곡선 미제공은 null과 사유. 없는 값을 0이나 추정치로 채우지 않는다. 그림에서 읽은 곡선은 근사치 표시.
- 노출 집단·기간 차이와 반례를 함께 남긴다. 커버/캡션 변경 시각도 기록한다.

## 5. 김꾼 제작에 반복해서 넣는 운영안

1. 기획 전: 같은 청자 문제·목적·길이·관측 창의 과거 사례, 반례, 미검증 가설을 읽는다. 최신 10개는 초기 목록이지 그 자체로 공정한 실험 표본이 아니다.
2. 소재 선택: 수환 경험과 실제 질문/공유 반응에서 후보를 찾고 ‘개인의 탓→구조적 원인→고칠 출구’라는 기존 방향을 유지한다. 반응을 얻기 위해 경험을 꾸미지 않는다.
3. 후킹/대본: 이번 편이 참고한 게시물·무엇을 유지하고 무엇 하나를 시험하는지 명시한다. 구간 역할(상황, 갈등, 구조적 진단, 증거, 실행 방법, CTA)은 실제 대본에 맞춰 태그하며 고정 초수 템플릿으로 강제하지 않는다.
4. 편집 후: 실제 최종 발화를 시간표로 만들고 커버·첫 화면과 연결한다. 유지율이 있다면 같은 초에 맞춰 본다. 특정 문장 이탈 원인은 가설로만 기록한다.
5. 발행 후: 기존 1·3·7일차 관측을 실제 경과시간과 함께 보존. 초기 지표는 진단, 7일차는 비교 자료로 사용한다. 현재 하루 수집은 정확히 24/72/168시간에 측정하는 예약이 아니므로 실제 관측 창을 사용한다.
6. 리뷰: 사실→대안 설명→잘된 점/아쉬운 점→다음 편 변경 1개. 자료가 없으면 판단 보류한다. 7일차에 노출이 적으면 그 사실과 수치를 남기며 유리한 날까지 창을 늘리지 않는다.
7. 다음 기획: 참고한 학습 ID를 남긴다. 이후 성과가 반대면 교훈을 수정한다. 모델 자체 재학습이나 자동 대본 확정·게시가 아니다.

예시(실험안이지 성과 결론이 아님): ‘첫 문장을 사장의 감정 설명에서 직원의 구체 상황으로 바꾸면 3초 스킵률이 낮아지는가?’ 주요 지표 스킵률, 함께 볼 지표 평균 시청·공유율, 길이/본문/CTA는 가급적 유지. 자연 배포 집단 차이가 남으므로 여러 유사 편에서 재검증한다.

## 6. 권장 구현 순서와 아직 안 한 일

1. 정기 수집기에 스킵률 추가 + 누락 처리/단위 테스트. 오늘은 2개 실API 검증만 했다.
2. 최근 10개 게시물과 실제 최종 영상·대본·커버 연결. 파일 후보와 내용 일치 확인 전 자동 확정 금지.
3. Instagram/Edits 유지율 화면의 본인 계정 제공 여부 확인. 웹 팔로우·팔로워 구분과 함께 API 밖 관측을 별도 저장.
4. 게시물·제작 버전·관측·실험·학습을 ID로 연결. 기존 content-intake의 Palmier 고정값과 버전 ID 설계는 현재 CapCut 운영에 맞게 보완 필요.
5. 소재·후킹·대본 시작 시 관련 성과를 실제로 읽고 근거를 남기는 단계로 연결. 기존 workflow의 성과 리추얼에 통합하며 별도 상충 규칙을 늘리지 않는다.

현재 완료는 조사와 제공 범위 실검증이다. 위 구조의 구현·과거 제작물 매칭·구간별 분석·검증된 제작 기준 반영은 아직 완료하지 않았다.
