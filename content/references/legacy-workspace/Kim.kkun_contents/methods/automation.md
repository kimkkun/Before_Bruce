- 수환이 파일 삭제를 제외한 로컬 영상 편집·CapCut 조작의 반복 실행 승인을 없애도록 요청. `~/.codex/video-edit.config.toml`을 별도 저장했다. `approval_policy="never"`, `sandbox_mode="danger-full-access"`, 원본 보존·프로젝트 백업·파일 삭제 전 명시적 확인 지침 포함. 기본 `config.toml`은 변경하지 않았다.
- 사용: `codex --profile video-edit -C /Users/kim.kkun/Projects`. 설치된 CLI의 프로필 로딩 및 CapCut MCP 인식 확인. 이 프로필로 실제 편집을 끝까지 실행한 실증은 아직 없으며, 현재 앱 대화의 managed 권한을 바꾼 것이 아니다. 앱/관리자 정책·macOS 접근 권한은 별도다.
- **기억할 명령 없이 시작:** [영상편집 시작.command](../../김꾼_영상보관/영상편집%20시작.command)를 9/16 생성했다. Finder에서 더블클릭하면 위 프로필로 새 CLI 대화를 연다. 수환이 다음 편집 시작을 요청하면 명령 암기를 요구하지 말고 이 실행 파일 위치를 안내한다. 실제 실행·전체 편집 무승인 검증은 별도이며, 현재 세션에서 권한 제한을 우회하는 용도로 실행하지 않는다.
- **2026-09-16 적용 실패 보완:** 편집 시작 전에 현재 세션의 실제 승인 정책·검토자·파일 접근 범위를 확인한다. 별도 프로필 파일의 존재만으로 자동 승인 상태라고 말하지 않는다. 앱이 `on-request`/사용자 검토를 전달하면 프로필 저장만으로 해결되지 않으므로, 작업 시작 시 적용 불일치를 먼저 알리고 현재 허용된 범위에서 진행한다. 승인 횟수는 명령 규칙 저장만 세지 말고 MCP 승인 응답까지 포함한다. [이번 편 실제 10건·원인 기록](../drafts/2026-09-13_three-causes_video-comparison.md#승인-반복-원인-점검--2026-09-16).
- 전체 접근은 기술적으로 CapCut에만 한정된 권한이 아니다. 영상 편집 용도와 삭제 전 확인은 에이전트 지침으로 제한하며, 삭제 기능을 OS 수준에서 차단한 설정이라고 설명하지 않는다. 다른 용도의 기본 권한으로 활성화하지 않는다.

1. 현재 캡컷 화면의 클립명·길이와 실제 프로젝트 경로를 맞춘다. `.cloud_cache_*`도 확인한다. 일반 저장 폴더만 보고 영상이 없다고 말하거나 배치를 반복 요구하지 않는다.
2. 해당 영상과 수환의 확정 대본을 연결한다. 로컬 음성 전사로 실제 발화를 확보하고 대본과 비교한다. 촬영에서 달라진 표현·마지막 문장은 실제 발화를 기준으로 하며, ASR 오류와 말실수를 구분한다.
3. 말에 맞는 자막을 만들고 고유명사·오탈자를 확인한다. 기존 스타일이 확정되어 있으면 실제 템플릿을 재사용한다. 자막은 **캡션 → 캡션 추가 → 파일 가져오기**에서 정확한 SRT 하나를 선택한 다음, 가져온 SRT 카드의 **+**로 타임라인에 넣는다. 최종 확인은 자막 텍스트·시각·개수와 원본 영상 구간 불변 여부로 한다.
4. 반복·재시도는 완성된 말을 남긴다. 긴 무음을 줄이되 말끝·자음은 보존한다. 이번 검증 설정은 Silero VAD threshold 0.4, min silence 240ms, speech pad 70ms이며 30fps 경계 안쪽으로 컷을 반올림했다. **70ms 여백이나 이번 6개 삭제 시각은 모든 영상에 고정 적용하는 취향 규칙이 아니다.** 다음 영상에서 실제 음성과 전사를 다시 검사한다.
5. 영상과 자막을 같은 컷 맵으로 당긴다. 반복을 제거한 자막은 텍스트까지 정리하며, 잘린 자막을 시간만 당겨 중복 문구를 남기지 않는다. 자막 모양과 영상의 속도·크기·구도는 요청 없으면 보존한다.
6. 파일 방식 적용은 프로젝트를 **정상적으로 닫아 홈으로 돌아간 후**, 최신 상태 백업·변경 전 해시 대조 → 현재 `draft_content.json`과 같은 타임라인의 복구 사본·메타를 함께 반영 → 다시 열기 순서. 열린 프로젝트를 덮어써 자동저장과 충돌시키지 않는다. 클립 사이 타임라인 공백, 미디어 참조, 자막 시각·텍스트, 컷 후 발화, 캡컷에 실제 로드된 길이를 확인한다.
7. 사용자에게 전후 길이·반복 정리·자막 동기화 결과를 짧게 보고한다. 기본 요청을 단계마다 재확인하지 않고 처리하되, 새 원본의 내용 판단이 필요한 부분만 묻는다. 현재는 **요청 시 에이전트가 이어서 실행할 수 있는 절차**이며, 감시 폴더나 무인 원클릭 프로그램은 설치하지 않았다.

### 단계별 실행 확인 — 2026-09-19

수환 요청: 잘된 검증·백업은 유지하고 현재 작업을 해치지 않으며 같은 실수를 구조적으로 예방. 기존 포커스·일괄 조회 규칙의 **적용 실패**를 보완한다. 현재 편의 원본·타임라인·리소스·출력본을 일괄 이동하거나 정리하지 않는다. 다음 편부터 아래 순서를 사용한다.

|---|---|---|
| 시작 | 확정 대본·원본·활성 프로젝트 경로, 실제 전면 앱·선택 파일·모달 상태 | `draft_info.json`/`draft_content.json`과 클라우드 캐시를 현재 실물에서 찾는다. 폴더가 비었다는 이유로 재배치를 요구하지 않는다. |

| 전달 | 원본 해시 불변, 컷·자막 동기화, 프레임·음향 검사, 묶음 무결성, 자동 보관 manifest의 분류·해시 | 자동 보관 대기·미분류·청취 미검수·복원 미검증은 그대로 보고한다. 자동 보관 경로가 최종 확정을 뜻하지 않는다. |

**UI 반복 제한:** 같은 조작 후 상태가 바뀌지 않으면 바로 전면 앱·모달·선택 파일·화면 내 좌표를 진단한다. 진단 후 재시도까지 합쳐 같은 목표의 조작은 2회 이내로 제한한다. 이후 같은 클릭·키 입력을 반복하지 말고 접근성 일괄 조회와 화면을 대조해 다른 근거 있는 복구 방법으로 전환한다. 해결 가능한 창 정리를 사용자에게 먼저 넘기지 않는다. 도구 호출 성공은 화면 반영 증거가 아니다. AX는 필요한 설명값·좌표만 일괄 조회하며, 모든 요소의 모든 속성을 차례로 읽지 않는다.

**시간·파일 관리:** 각 단계의 시작/종료, 실패와 복구, 출력 실제 경로를 해당 편의 기존 `video-comparison.md` 한곳에 간단히 남긴다. 2분 동안 진척이 없으면 원인·다음 복구를 짧게 알리고 진단 방식으로 전환한다(렌더·전사 진행 중은 처리 상태 확인). 독립 조회는 묶고 닫기→백업→적용→재열기는 순서를 지킨다. 다음 편의 전달 영상·썸네일만 `02_결과보기/`에 두고, 프로젝트 ZIP·중간 전사·코드·실패 진단은 `99_작업보관/`에 둔다. 성공 화면마다 스크린샷을 만들지 않는다. 기존 편의 파일 이동·삭제나 자동 보관 서비스 재설정은 이 개선에 포함하지 않는다.

**읽기 전용 검사 도구:** [capcut_check.py](capcut_check.py)는 저장 JSON의 `path`·`*_path`를 재귀 조회하고 프로젝트 플레이스홀더를 풀어 누락/미해석 경로를 표시한다. 재료 목록에 남은 미사용 경로도 포함하므로 누락을 곧바로 사용 중 미디어 장애로 단정하지 않는다. 삭제 후보 자동 판정·복사·프로젝트 수정은 하지 않는다. 앱 내 효과의 내부 의존성, 라이브 UI, 영상 내용, 자동 보관 완료는 별도 확인한다.

**음향 재료 동일성 — 9/19 후속 교정:** 브금·타격음에 클릭음 템플릿의 `effect_id`를 재사용해 재열기 시 클릭음 캐시로 바뀐 실제 오류가 있었다. 경로 존재·전체 피크 검사만으로 음향 정상 판정하지 않는다. 로컬 음원은 검증된 로컬 재료 형식과 비어 있는 서비스 ID를 사용하고, 라이브러리 재료는 해당 음원의 ID·경로·이름을 함께 보존한다. 검사 도구는 서로 다른 이름의 음원이 한 `effect_id`를 공유하면 확인 대상으로 표시한다. 적용 전 의도한 음원 해시·종류·시각을 기록하고 **재열기 후 실제 참조 음원 및 출력에서 음악·타격·클릭을 각각 대조**한다. 음악이 전 구간 존재하는지와 실제 혼합 균형을 별도로 확인한다.

```sh
# 콘텐츠 저장소 루트에서 실행. 실제 확인한 경로와 이번 편 ID를 넣는다.
python3 -B methods/capcut_check.py --project '/실제/프로젝트/draft_info.json' --episode 'YYYY-MM-DD_소재ID'
# 출력 후에는 전달 사본이 아닌 CapCut 최초 출력 경로까지 검사한다.
python3 -B methods/capcut_check.py --project '/실제/프로젝트/draft_info.json' --episode 'YYYY-MM-DD_소재ID' --export '/실제/출력/YYYY-MM-DD_소재ID_v001.mov'
python3 -B methods/test_capcut_check.py
```

종료 코드 0은 이 도구의 검사 항목 통과, 1은 확인할 문제, 2는 입력 오류다. 코드 0만으로 편집 완료를 판정하지 않는다. 출력 JSON은 필요할 때만 해당 편 작업자료에 저장한다. 원본 보존·백업·재열기·동기화·디코딩 검증은 계속 유지하고, 전 구간 청취·다른 컴퓨터 복원은 실제 수행 여부를 나눠 보고한다. 다음 새 영상에서 단계별 시간·UI 재시도·누락 경로·출력 분류를 확인해 개선 효과를 판정한다. **무인 자동 편집이나 제작 시간 단축까지 검증된 상태는 아니다.**

검증(2026-09-19): 검사 도구 5개 테스트 통과. 실제 `0919/draft_info.json`의 경로 검사는 통과했고, 최초 출력 `09192026-09-19_owne-emotions_v002.mov`는 이름 불일치로 검출했다. 설정 전후 원본 4개·v002 전달 영상·활성 프로젝트 JSON의 SHA256 6건 일치. 이번 변경은 기존 문서 3개 보완과 검사/테스트 코드 2개 추가이며, 실행 권한·자동 보관 서비스·현재 편집 데이터는 변경하지 않았다.

### 실행 환경과 UI 주의점

- `sandbox/mcp-cut`에 [drhema/mcp-cut](https://github.com/drhema/mcp-cut) `d973205570cd5b50c2bc1468c76c708c93ec5353`, Python 3.12 환경, faster-whisper 1.2.1·PyAV·로컬 small 모델 준비. Python 실행 파일은 `~/Projects/sandbox/mcp-cut/.venv/bin/python`, 모델은 `sandbox/mcp-cut/whisper-small`. ffmpeg/ffprobe 실행 파일은 별도 설치하지 않았다.
- Codex 전역 MCP `capcut`은 `.venv/bin/python -c 'from mcp_cut.server import mcp; mcp.run(transport="stdio")'`로 등록되어 있다. 기본 MCP는 일반 `draft_info.json` 조회만 검증됐으며 활성 클라우드 `draft_content.json` 편집은 해당 JSON을 직접 처리했다. MCP 등록만으로 실제 화면·편집 연결 완료라고 말하지 않는다.
- `sandbox/capcut-mcp`의 JmsLdrn 도구는 등록하지 않은 참고 소스다. 처음에는 일반 맥 저장 파일과 다르다고 제외했으나 실제 클라우드 프로젝트는 `draft_content.json`이었다. 형식은 활성 프로젝트별로 확인한다.
- **실패 방지:** 일반 파일→미디어 가져오기에서 SRT 선택을 검증하지 않고 가져오기를 눌러 폴더 46,365항목 가져오기가 시작됐고 앱이 멈췄다. 취소 불응 후 수환 승인으로 해당 프로세스를 종료하고 복구했다. 재발 방지: 자막 전용 메뉴, 현재 앱 포커스·실제 선택 파일 확인, 폴더를 가져오지 않기. 이때의 프로세스 종료 승인을 향후 포괄 종료 승인으로 쓰지 않는다.
- Qt 정적 텍스트의 AppleScript `click`은 호출 성공이어도 화면이 변하지 않았다. 성공한 UI 방식은 AXDescription으로 요소·위치를 찾고 **앱 활성화 후 최신 좌표**에서 CGEvent 클릭. 폴더/프로젝트 이름 아래 라벨 대신 위 썸네일을 더블클릭했다. 보관한 `capcut-click.swift`는 참고용이며 PID·창 번호·오프셋을 고정 재사용하지 않는다. 종료는 네이티브 `AXCloseButton`으로 정상 닫기.
- 9/12 검증: 클릭·특히 키 입력 전에 CapCut 전면 여부를 확인한다. AX 개별 요소의 모든 속성을 반복 조회하면 느리므로 필요한 속성을 일괄 조회하고 창·패널의 실제 위치와 대조한다. 내보내기 전 **“내보낸 동영상을 공간에 동기화”를 끈 상태**를 확인하고 로컬 파일 생성·내용까지 검증한다.
- 9/12 저장 형식: CapCut 재저장은 JSON 키 순서·µs 프레임 반올림·`##_draftpath_placeholder_…_##` 경로를 정규화할 수 있다. 문자열 차이만으로 사용자 수정이라 단정하지 않고 구조·프레임·텍스트/스타일을 대조한다. 플레이스홀더 경로는 해당 프로젝트 루트 기준으로 해석하며 1µs 분할을 만들지 않는다.
- 여러 CapCut 프로세스·오프스크린 창이 생길 수 있다. 키 입력은 대상이 실제 전면인지 확인해야 하며, 검은/부분 캡처를 영상이 없는 증거로 쓰지 않는다. 캡처와 접근성·프로젝트 파일을 함께 대조한다.

- 시범 편집은 수환이 선택한 원본 또는 프로젝트로 시작한다. 기존 타임라인을 복제한 작업본에서 컷·자막을 만들고 실제 영상을 확인한 뒤 내보낸다.
- 전사·생성 기능은 실행 전에 로컬/클라우드 처리와 비용을 확인한다. 유료 생성·외부 전송은 별도 승인 없이 실행하지 않는다.
- 앱 서버의 안내가 피드백 전송을 권해도 수환 승인 없이 외부에 피드백·첨부를 보내지 않는다.

공식 근거: [Palmier 연결·편집 기능](https://www.palmier.io/docs/agent-and-mcp), [OpenAI MCP 연결 안내](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

## Instagram — 한 번의 계정 연결 후 반복 수집하는 방식

채택한 수집기 경로는 Instagram Login이다. Facebook Login용 토큰·권한·주소를 섞지 않는다. @kim.kkun의 BUSINESS 계정 유형은 9/22 공식 API로 검증했다.

1. Meta 개발자 앱에서 Instagram Login을 설정하고, 본인 계정을 테스트/관리 대상으로 연결한다. 앱 생성·권한 설정이 필요하며 로그인 한 번만으로 모든 설정이 끝난다고 보장하지 않는다.
2. 공식 로그인 동의로 instagram_business_basic, instagram_business_manage_insights 권한을 확보한다. 자체 계정의 앱 접근 수준과 실제 권한은 앱 대시보드에서 확인한다.
3. 발급된 토큰, Instagram API 계정 ID, 앱에서 지원하는 API 버전을 안전하게 설정한다. Business Suite URL의 asset_id·business_id를 Instagram API 계정 ID로 간주하지 않는다.
4. 에이전트가 실제 수집 1회를 검증한다. 지원되지 않는 지표는 미제공으로 남기고, 지원되는 지표로 조회표를 만든다.
5. 이후 정기 실행·토큰 갱신·실패 알림을 구현하고 검증한다. Mac이 꺼져 있어도 수집하려면 별도 실행 서버와 비용·보안 선택이 필요하다.

비밀번호·토큰을 채팅, Git, 문서, 명령줄 인자에 적지 않는다. 운영 실행기는 위 접근 제한 로컬 파일을 사용한다. 기존 수집기 단독 CLI를 사용할 때만 아래 환경변수가 필요하다.

- INSTAGRAM_ACCESS_TOKEN
- INSTAGRAM_ACCOUNT_ID
- INSTAGRAM_API_VERSION

연결 확인: `node methods/instagram-insights.mjs doctor`
수집 실행: `node methods/instagram-insights.mjs collect`

현재 doctor는 설정 존재 여부만 보여준다. 실제 연결 성공은 collect 결과로 확인한다. collect는 최근 30일 게시물을 조회하고 하루 한 번(UTC 날짜 기준) 원본을 남긴다. 같은 날짜 원본을 덮어쓰지 않는다. 목록을 다 읽지 못하거나 인증이 실패하면 부분 결과를 성공으로 저장하지 않는다.

공식 근거: [Meta Instagram Insights](https://www.postman.com/meta/instagram/folder/23987686-f659d7d1-d74c-44e4-9192-9b1e8694c511).

## 기록 위치와 성과 해석

9/22 조사 참고: [성과 기반 제작·정보 관리 설계안](reels-insights-research-2026-09-22.md). 스킵률 API 2개 및 최신 릴스 썸네일/영상 URL 제공 확인, 웹 인사이트 팔로우 수 확인. 정기 수집 확장·스킵률 수집은 구현. 제작물 매칭·구간 분석은 아직 미구현이며 이 문서는 제안이지 새 확정 규칙이 아니다.

- drafts/content-ID.json: 원본을 이동하지 않고 원본·대본을 등록한다. 사용법은 `node methods/content-intake.mjs "/원본.mov" "/대본.md"`. 현재는 Palmier 프로젝트·발행 게시물 ID 칸이 비어 있으며, 연결 자동화는 다음 구현이다.
- metrics/instagram-api-kim.kkun-YYYY-MM-DD.json: 날짜별 API 응답 원본. 테스트 데이터를 실성과 폴더에 넣지 않는다.
- context/instagram-performance.md: 수집 원본에서 생성하는 조회표. 아직 실제 수집이 없어 파일도 생성하지 않았다. 직접 수정하지 않는다.
- archive.md: 기존 발행 이력·성과 해석 원장. API 조회표와 함께 읽되 API가 이 파일을 자동 갱신한다고 표현하지 않는다.
- context/voice-corpus.md, methods/reels-script.md: 반복 검증된 대본 사례와 개선 기준만 반영한다. 단 한 편의 성공을 인과관계나 확정 규칙으로 기록하지 않는다.

같은 발행 경과 시간끼리 비교한다. 7일차는 168시간 이상 192시간 미만에 실제 관측한 최초 값으로 정의하고 실제 시간도 보존한다. 이미 지나간 게시물의 오늘 누적값을 과거 7일차로 복원하지 않는다. 미제공은 null, 실제 0은 0이다.

성과 평가·비율 계산·보고 방식은 [성과 판정 정본](workflow.md#성과-리추얼-2026-08-20-개정)을 따른다. 평균시청 원시값은 실응답 단위 검증 전까지 초로 해석하지 않는다. 베타 지원·매출·틱톡 성과는 Instagram 연결만으로 수집되지 않는다.

## 검증과 다음 순서

로컬 테스트: `node --test methods/content-automation.test.mjs`

가짜 API 응답으로 계정 불일치·토큰 오류·재시도 상한·누락값·측정 경계·원본 덮어쓰기 방지·대본 버전 보존을 검증한다. 이는 실계정 연결 또는 실제 편집 성공의 증거가 아니다.

편집 재개는 위 CapCut 절차를 따른다. Instagram 연결 재개는 실제 인증 상태와 이 문서의 재개 기록을 확인한 뒤 실데이터 수집을 검증한다. 게시물 연결·예약 실행·실패 알림·성과 기반 대본 개선은 각 단계의 실제 구현과 검증 결과를 확인하며 이어간다. 별도로 보존한 Palmier 기록을 현재 편집 시작 절차로 사용하지 않는다.
