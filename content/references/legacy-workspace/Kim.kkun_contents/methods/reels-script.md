# methods/reels-script — 릴스 대본 방법론

> 기존 kimkkun-reels-script 스킬(Cowork)을 흡수한 SSOT. 스킬과 충돌하면 이 파일이 우선.
> 변경 이력: 길이 90~130초 → **60~90초** (2026-07-25 수환 결정) / 출고 패키지 6종 신설 / AI티 검수 추가 / 지표 매핑 교정.
> 현재 길이·긴 영상 허용 조건·첫 30초 기준은 [작동 지침](../CLAUDE.md)의 「영상 길이·30초 벽 정본」을 따른다. 위 길이 변경은 당시 이력이다.

## 0. 전제

- 화자 = 김꾼. 사고방식·거부 목록은 `context/kimkkun-mind.md`, 청자는 `context/audience.md`, 톤 앵커는 `context/voice-corpus.md` **원문**이다. 규칙 서술과 원문이 다르면 원문이 이긴다.
- 사례 풀: 스키당 운영 경험 + 자영업 10년 누적 + 컨설팅 케이스만. **일등고기 금지. 실재 불확실한 일화는 수환에게 확인.**
- 입말은 수환이 촬영하며 입힌다 — 대본은 **뼈대(구조·논리·단언)의 정확성**이 합격 기준. 단, 구어 텍스처 장치는 심어둔다 (아래 §3).

## 1. 출고 패키지 (소재 1개당 6종)

1. **POV 제목 2~3안** — 후킹되는 상황형 제목 (커버·도입 자막용)
2. **훅 5개** — 유형 다르게: 단언+수치형(기본값), 구조 예고형, 행동 저격형, 죄 전환형, 상황(POV)형. 질문형은 보조로만 (검증 성과 최하위)
3. **본문 대본** — 작동 지침의 길이·구조 기준 적용, 모드 명시, 검수 기록 첨부
4. **캡션** — 첫 125자 안에 승부 (피드 잘림선). 구성: 첫 줄 훅(대본 훅과 다르게 재작성) + 2~4줄 핵심 요약 + CTA + **해시태그 최대 5개** (수환 교정 2026-07-25: 인스타 정책 기준. 5개 초과 금지)
5. **썸네일 카피 2~3안 + 지시** — 프레임 지시(표정·구도) + 얹을 문구. 캡컷에서 30초 작업 가능한 수준으로
6. **블로그 글** — 대본 승인 후 `methods/longform.md`로

## 2. 김꾼 톤 (스킬 이식 — 핵심)

한 줄 정의: **확실히 아는 사람. 날카롭지만, 친근한.** 한발 앞선 형/선배. 선생님 아님.

- **어미**: 기본은 요체로 풀고, 합쇼체는 단언을 찍는 자리에 쓴다. 기존 7:3은 참고 관찰이며 비율을 맞추려고 문장을 고치지 않는다.
- **"~잖아요?"·"~거든요?"** 등은 동의·설명이 자연스럽게 이어지는 자리에만 쓴다. 최소 횟수를 두지 않고 반복을 억지로 넣지 않는다. 반말 절대 금지.
- **말투 보완**: [코퍼스의 말투 반영 절차](../context/voice-corpus.md#말투를-계속-반영하는-방법)에 따라 수환의 직접 수정·확인된 실제 발화를 참고한다. 최근의 명시적 교정을 우선하고 소재·감정에 맞춰 적용한다.
- 본인 호명 "김꾼입니다." — 훅 직후, 단정하게.
- 체류 강요("끝까지 보세요") 금지. 이모지 금지. 자기검증 멘트 1회 이내.
- 균형 멘트 1회 (꼰대 방지 안전장치).

**구어 텍스처 장치 (필요한 자리에만):** 자문자답 / 끊어치기·도치 / **대사 직접 인용**(사장 속마음·직원 번역·리뷰 원문) / 강조 부사. “진짜로요”처럼 의미 없이 강조만 하는 추임새는 넣지 않는다. 장치별 횟수를 채우려고 문구를 덧붙이지 않는다. (2026-09-09 수환 교정)

## 3. 4모드

### 수환이 지정한 최신 더크루 대본 스타일 (2026-09-15)

2026-09-19 추가 지정: 인간적인 경험 서사는 [수환 수정본 비교에서 확정한 기준](../context/voice-corpus.md#수환-지정-참조--인간적인-경험-서사-2026-09-19)을 함께 적용한다. 고민·시도·기존 방법의 한계·직접 만들게 된 이유를 충분히 연결한다. 아래 항목형 구조는 소재에 맞게 선택하며 모든 대본을 개수 예고형으로 만들지 않는다.

정본 예시: [사장 편 수환 수정 원문](../drafts/2026-09-13_owner-three-points_suhwan-edit.md). 근거 발언: “기록해둬 다음번에 이런 식으로 써야 됨”. 발행 성과가 검증된 코퍼스와는 구분한다.

- 도입은 문제를 세게 단언하고 개수를 예고 → 짧은 경험 고백 → “김꾼입니다”. 이 원문처럼 항목 이름은 본문에서 풀어도 된다.
- 각 항목은 현장 대사·상황 → 사장이 겪는 부담 → 더크루 해결 방식 순으로 바로 연결한다. 세 문제를 전부 설명한 뒤 제품을 몰아서 소개하지 않는다.
- 설명을 반복하거나 가상의 속마음을 길게 덧붙이지 않는다. “땜빵”, “이게 제일 뼈아픕니다”처럼 수환의 직접적인 표현과 짧은 전환을 참조한다.
- 해결은 사용 장면까지 구체화한다. 같은 작업 기준을 보기, 빠진 일을 이어받기, 기록을 보고 업무를 나누고 구체적으로 인정하기. 사장에게 무엇이 편해지는지까지 연결한다.
- 결말은 시스템을 갖춘 사장의 주도권·역할 변화로 끌어올리고, 더크루를 만드는 이유로 닫는다. 이번 원문의 “슈퍼파워를 가진 진짜 사장님”을 그 방향의 예시로 삼는다.
- 위는 구조·표현의 참조다. 새 대본의 실제 경험·기능 상태·효과 주장은 기존 근거 확인 기준을 적용하며, 원문의 단언을 제품 효과의 실측 근거로 취급하지 않는다.

| 모드 | 언제 | 목적 |
|---|---|---|
| A 인사이트형 | 구조·원리를 가르칠 때 | 신규 유입 ("몰랐는데 알게 됐다") |
| B 재정의형 | 한 단어를 분해·재조립 | 공유 ⚠️ AI티 최위험 모드 — §5 검수 강화 |
| C 메타형 | 사고 프레임 자체를 바꿀 때 | 브랜드 자산 ("사고력 다르네") |
| D 추천형 | 본인 판단을 받게 만들 때 | 권위 |

구조 공통 골격 (60~90초 기준): 훅(3~8초) → 본인 호명 → 전개 2~3챕터 (챕터당 비유 1 or 대비 인사이트 1, 추상엔 반드시 구체 착지) → 마지막 한 줄 시니컬 단언 (클립용, 손에 잡히게) → CTA (선택 — archive 데이터 따라).
스킬의 모드별 상세 템플릿·완성 예시(references/)는 참고하되, **60~90초에서는 챕터 2개가 기본**이다.
긴 영상은 소재에 필요한 전개로 구성하고, 위 짧은 영상용 챕터 수에 억지로 맞추지 않는다. 검수에서는 작동 지침의 긴 영상 허용 조건과 첫 30초 기준을 함께 확인한다.

**검증 골격 "에이스 구조" (2026-08-25 등재, 35.6만/3일차 — 원문·해부는 context/voice-corpus.md #6):** 콜드오픈 스킷(결과 장면 먼저, 0~5s) → 죄 전환 재정의 훅 + 호명 → 고백(10초 안) + 넘버링 예고 → 물리 법칙 챕터(원리 1문장 + 호명 반복 + 훅 회수) → 직원 내면 번역 3단계 챕터(마지막 신호 대사로 마감) → 고백 확장 + 해법 정의 한 줄 + 실물 착지 → 경구 단언 + CTA. 사장 시점과 직원 시점을 한 대본에 공존시키는 것이 핵심. 더크루 서사 대본은 이 골격을 기본값으로 변주한다.

## 4. 작업 흐름

진행·제출·승인 절차는 [세션 절차](workflow.md#대본-세션-카드-확정-후)를 따른다.

소재 방향이 확정되면 에이전트가 **모드 판단 → 훅 후보 작성·추천 → 구조 설계 → 풀 대본 → 검수** 순서로 작업한다. 훅 선택·구조 합의를 필수 중간 승인으로 요구하지 않고, 검수한 출고 묶음을 한 번에 제출한다. 실제 경험·주장 근거가 부족해 대본에 영향을 주는 경우에는 기존 자료부터 확인하고 필요한 질문만 한다.
소재가 여러 개여도 같은 기준을 적용한다. 수환이 훅이나 구조부터 함께 보자고 요청한 경우에는 그 순서로 진행한다.

## 5. 검수 (출력 직전 필수 — 기록 첨부)

- **점검 1 사업 회수**: 마지막 단언이 김꾼 사업(코칭·콘텐츠) 또는 스키당(공간·시간 가치)과 같은 방향인가.
- **점검 2 4대 욕구**: 최소 2개 (audience.md).
- **점검 3 의미 게이트 (수환 기준)**: ① 계속 듣고 싶은가(내용 후킹) ② 감정이 동요되는가 ③ 배웠다는 느낌 ④ 행동 유발 — 4문 중 3개 이상 예.
- **점검 4 톤**: 수환 원문·최근 교정과 어울리는 말투인가 / 어미·추임새를 횟수나 비율 때문에 억지로 넣지 않았나 / 요체·합쇼체 배치 / 구어 텍스처 실재 / 마지막 시니컬 단언 / 균형 멘트 1회 / 선생님 톤 아닌가.
- **점검 5 논리**: 선언 점프 금지(모든 단언에 '왜') / 예시→증거 회수 / 훅-본문 프레임 일관 / 마지막 단언 모순 체크 / 청자가 자기 가게에 갖다 댈 기준 한 줄.
- **점검 6 AI티 (신설)**: "X가 아니라 Y다" 구문 대본당 2회 이하 (AI 1번 시그니처 — B모드에서 특히) / 3항 나열 반복 없나 / 대칭 구문으로 통찰 흉내 없나 / 기성품 공감 표현 없나 / 근거 없는 숫자 없나(거부 목록).
- **점검 7 책임 재배치**: 탓이 개인→구조로 이동하고 출구가 있는가 (kimkkun-mind §1·§3).

## 6. 지표 언어

- 성과의 핵심 지표·계산식·비교 조건은 [성과 판정 정본](workflow.md#성과-리추얼-2026-08-20-개정)을 따른다. 실제 제공된 지표로 판단하고 평균 시청 시간과 완주율을 구분한다. 플랫폼의 추천 신호와 우리 콘텐츠의 성과 판정 기준을 혼동하지 않는다.
- "첫 3초가 결정적"은 공식 프레임 — 쓴다. "이탈 50~60%" 같은 수치는 근거 없음 — 쓰지 않는다.
- 최적 길이는 없다 (길이는 같은 길이대 안에서 정규화됨). 길이는 작동 지침의 기본값과 허용 조건을 적용하고 archive로 자체 실증한다.
