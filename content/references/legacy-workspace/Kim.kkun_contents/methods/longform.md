# methods/longform — 블로그 글 방법론 (매거진형 웹사이트행)

> 대본 승인 후, 같은 소재 카드에서 뽑는다. 늘리기가 아니라 **복원**이다.

## 역할 정의 (검증 반영)

블로그는 릴스 트래픽 받는 그릇이 아니다 (릴스→외부 유입은 구조적으로 작음 — 검증됨). 역할은 셋:
① 검색으로 들어오는 별도 유입구 ② 코칭·강의의 신뢰 자산 ("이 사람 진짜네") ③ 릴스에서 못 다한 근거의 아카이브.

## 복원 원칙

릴스 대본은 압축본이다. 글에서는 카드에 적재된 것을 복원한다:
- **근거·데이터** (출처 필수 — 근거 없는 숫자는 거부 목록) / **업종별 사례 확장** (릴스 1개 → 글 2~3개) / **배경 맥락·반론 처리** ("이런 반박이 있을 수 있는데") / **수환 경험담의 디테일** (릴스에서 잘린 부분)
- 전사 금지: 대본을 받아쓰면 글이 안 된다. 글의 논리 순서로 재배열.

## 구조

- **제목 + 첫 두 문장 = 글의 훅. 대본 훅 이식 금지, 새로 쓴다** (검색 유입 고려 — 사장님이 검색할 말로).
- 소제목 2~4개로 스캔 가능하게. 소제목은 주장형 (김꾼 카드뉴스 원칙과 동일).
- 마지막: 시니컬 단언 + 출구(구체 행동 1개) — 릴스와 같은 착지 문법.
- 분량: **1,500~2,000자대 기본, 소재가 요구하면 초과 허용.** 글자수는 목표가 아니라 결과 (글자수-성과 상관은 근거 없음이 검증됨 — 구조가 품질을 결정한다).

## 톤

김꾼 사고방식(kimkkun-mind) 동일. 단 글은 토킹헤드가 아니므로: "~잖아요" 빈도 낮춤 (글에서 과하면 어색), 문어 허용도 높음, 대사 인용·넘버링 프레임은 글에서도 강력 — 유지.
AI티 검수 동일 적용 (reels-script §5 점검 6).

## 출력 양식

```
## [김꾼 블로그 — '소재명' / 약 N자]
# 제목 (검색어 고려 2안)
본문 (소제목 구조)
---
### 복원 내역 (대본 대비 뭘 복원했나: 근거 N개·사례 N개·반론 N개)
### 검수: AI티 ✓ / 근거 출처 ✓ / 착지 ✓
```
