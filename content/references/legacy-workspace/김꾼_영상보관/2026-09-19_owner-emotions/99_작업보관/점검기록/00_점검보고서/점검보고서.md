# 문제 원인과 결과물의 한계

복구해서 출력한 사실과, 처음부터 제대로 진행한 것은 구분해야 한다.

## 1. 선택 완료 상태를 놓치고 같은 입력을 반복

원본 MOV는 이미 선택돼 있었다. 하위창이 남았다는 정보만 보고 경로 입력·확인을 반복했다. 선택 파일을 읽고 가져오기 버튼을 실행하자 해결됐다. 처음부터 해야 했던 확인이다.

## 2. 포커스·안내창·화면 밖 좌표를 먼저 정리하지 않음

터미널이 앞에 있거나 EditPilot 안내가 떠 있는데도 클릭·키 입력을 이어갔다. 도구 호출 성공을 실제 UI 반영으로 오인했다. 사용자에게 창 정리를 넘긴 시점도 너무 빨랐다.

## 3. 기존 리소스 경로·접근 가능성을 적용 전에 검증하지 않음

이전 편 캐시 경로가 현재 존재하지 않았고 외부 자료는 CapCut에서 누락으로 표시됐다. 프로젝트 내부 사본으로 복구했다. 파일 존재 확인만으로 앱에서 사용할 수 있다고 판단한 것이 부족했다.

## 4. 출력명 오류를 남겨 자동 보관 분류까지 어긋남

원출력명이 09192026-09-19_owne-emotions_v002.mov로 남았다. 전달 파일은 올바른 이름으로 복사했지만 자동 보관본은 분류 대기에 들어갔다. 이전 완료 보고에 이 영향이 빠졌다.

## 검수 수준도 정확히 표시해야 한다

파일 손상·프레임·해시·클리핑 검사와 대표 장면 확인은 완료. 전 구간 사람 청취는 미실행이다. 썸네일은 별도 디자인이 아니라 제목이 있는 도입 프레임 추출 시안이다. 미적용 초안 SRT와 버전별 작업 파일은 최종 전달본과 분리해서 봐야 한다.
